# DolphinScheduler源码教材 - 模块架构篇

## 概述

DolphinScheduler是一个分布式工作流调度系统，采用分层架构设计，各模块职责清晰。本教材将深入解析各模块的设计理念和实现原理。

## 核心模块架构

### 1. Master模块 - "总指挥部"

Master是整个调度系统的核心，就像一个总指挥部，负责统筹规划和资源调度。

#### 1.1 模块结构
```
dolphinscheduler-master/
├── engine/                    # 执行引擎
│   ├── workflow/             # 工作流引擎
│   │   ├── trigger/         # 触发器（手动/定时）
│   │   ├── statemachine/    # 状态机
│   │   └── lifecycle/       # 生命周期管理
│   ├── task/                # 任务引擎
│   │   ├── client/          # 任务执行客户端
│   │   ├── dispatcher/      # 任务分发器
│   │   └── runnable/        # 任务运行实体
│   └── coordinator/         # 协调器
├── exception/               # 异常处理
├── registry/                # 注册中心
└── runner/                  # 运行器
```

#### 1.2 核心组件详解

**MasterCoordinator - 总协调员**
```java
// 作用：Master集群的协调者，确保高可用性
// 类比：像一个项目总监，负责协调各个部门的工作
@Component
public class MasterCoordinator {
    // 负责启动和停止Master的各个子系统
    // 管理分布式锁，确保同一时刻只有一个活跃协调器
}
```

**WorkflowEngine - 工作流引擎**
- 触发器模块：处理工作流的启动请求
  - `WorkflowManualTrigger`：处理手动触发
  - `WorkflowScheduleTrigger`：处理定时触发
- 状态机模块：管理工作流状态转换
- 生命周期模块：处理工作流各阶段事件

**TaskEngine - 任务引擎**
- 客户端模块：与Worker通信
- 分发器模块：任务分发到合适的Worker
- 运行实体模块：任务的具体执行逻辑

### 2. Worker模块 - "执行部队"

Worker是具体的任务执行者，就像执行部队，负责执行Master分发的具体任务。

#### 2.1 模块结构
```
dolphinscheduler-worker/
├── executor/                # 任务执行器
│   ├── physical/           # 物理任务执行器
│   ├── logic/              # 逻辑任务执行器
│   └── container/          # 任务容器管理
├── registry/               # 服务注册
├── rpc/                    # RPC通信
└── server/                 # 服务器组件
```

#### 2.2 执行器架构

**物理任务执行器**
- Shell任务执行器
- SQL任务执行器
- Python任务执行器
- 各种插件任务执行器

**逻辑任务执行器**
- 条件任务执行器
- 依赖检查执行器
- 子工作流执行器

### 3. Registry模块 - "通讯中心"

Registry模块负责服务发现和注册，就像一个通讯中心，让各个节点能够相互找到和通信。

#### 3.1 支持的注册中心
- **Zookeeper注册中心**：传统的分布式协调服务
- **Raft注册中心**：基于Raft算法的内置注册中心
- **ETCD注册中心**：云原生环境的首选

#### 3.2 注册中心功能
- 服务注册与发现
- 配置管理
- 分布式锁
- 集群选主

### 4. API模块 - "对外窗口"

API模块提供REST接口，是系统的对外窗口。

#### 4.1 主要接口分类
- 工作流管理接口
- 任务定义接口
- 调度配置接口
- 监控统计接口

### 5. Alert模块 - "报警系统"

Alert模块负责系统告警，支持多种告警方式。

#### 5.1 告警类型
- 邮件告警
- 钉钉告警
- 企业微信告警
- 自定义告警插件

## 模块间通信机制

### 1. Master-Worker通信
- **RPC通信**：基于gRPC的高效通信
- **心跳机制**：定期检查节点状态
- **任务分发**：Master向Worker分发任务
- **状态汇报**：Worker向Master汇报执行状态

### 2. 事件驱动架构
```java
// 事件总线模式
WorkflowEventBus -> 发布事件 -> 事件处理器 -> 状态变更
```

### 3. 分布式锁机制
- 保证Master协调器的唯一性
- 确保工作流实例不重复执行
- 维护集群状态一致性

## 高可用架构设计

### 1. Master高可用
- **多Master部署**：支持多个Master节点
- **主备切换**：故障时自动切换
- **负载均衡**：Master间负载分担

### 2. Worker高可用
- **工作组机制**：按组管理Worker
- **故障转移**：Worker故障时任务重新分配
- **资源隔离**：不同工作组资源隔离

### 3. 数据高可用
- **数据库集群**：支持主从复制
- **数据持久化**：确保数据不丢失
- **定时备份**：定期备份重要数据

## 扩展性设计

### 1. 插件化架构
- **任务插件**：支持自定义任务类型
- **告警插件**：支持自定义告警方式
- **注册中心插件**：支持多种注册中心

### 2. SPI机制
- 通过SPI机制加载插件
- 运行时动态发现和加载组件

### 3. 配置化设计
- 大部分功能通过配置文件控制
- 支持动态配置更新

## 小结

DolphinScheduler的模块架构设计充分考虑了分布式系统的特点：

1. **职责清晰**：每个模块职责明确，低耦合高内聚
2. **高可用性**：通过冗余和故障转移保证系统可用性
3. **可扩展性**：通过插件化和配置化支持系统扩展
4. **高性能**：通过异步处理和事件驱动提升性能

这种架构设计让DolphinScheduler能够在大规模分布式环境下稳定运行，同时保持良好的扩展性和维护性。
